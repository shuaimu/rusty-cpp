# `alloc` — vendored snapshot of the consolidated Rust `alloc` port

`alloc.cppm` is generated, not hand-written. It is the whole of Rust's `alloc`
crate transpiled into ONE C++20 module: `raw_vec`, `boxed`, `string`, `borrow`,
`rc`, `sync` (Arc), `collections` (`vec_deque`, `binary_heap`, `linked_list`,
`btree_map`/`btree_set`) and `vec`.

It is vendored so the CMake build is hermetic — building the test suites must
not require a rustc source tree or `cargo-expand`.

## Regenerating

```sh
bash docs/alloc/build.sh /path/to/workdir
cp /path/to/workdir/out/alloc.cppm transpiled/alloc/alloc.cppm
```

`build.sh` copies Rust's `alloc` sources out of
`$(rustc --print sysroot)/lib/rustlib/src/rust/library/alloc/src`, runs
`docs/alloc/prep.sh` over them, transpiles with `--expand`, then applies
`docs/alloc/post_transpile_patch.py`. Every divergence from a plain transpile
lives in that patcher as a named rule — do not hand-edit `alloc.cppm`, or the
next regeneration silently drops the change.

⚠️ `cargo-expand` is PINNED to 1.0.95. Newer versions change the expansion
shape enough to break `BorrowType` recovery in the btree code and to flip the
patcher's const anchors.

## Consumers

`vec_tests_port` and `vec_deque_tests_port` bind this module's
`vec::Vec` / `collections::vec_deque::VecDeque`. After regenerating, rebuild
and re-run both suites — they are the regression gate for this snapshot:

```sh
ninja -C .rusty-modules-cache/build vec_tests_port_module_test.out \
                                    vec_deque_tests_port_module_test.out
./.rusty-modules-cache/build/vec_tests_port_module_test.out        # 151 tests
./.rusty-modules-cache/build/vec_deque_tests_port_module_test.out  # 104 tests
```

The suites themselves are regenerated by `docs/vec_tests_port/` and
`docs/vec_deque_tests_port/` (see those directories' patchers). Their cited
skips can be re-checked without editing the skip list:
`RUSTY_VEC_UNSKIP=test_name,... python3 docs/vec_tests_port/post_transpile_patch.py <out>`.
